# 药品有效期管理 · 免邮箱同步版

## 部署

1. 打开你的 Supabase 项目，在 SQL Editor 中运行 `schema-sync-code.sql`。这个脚本建立独立的同步空间表和访问函数，不删除原有 `drugs` 表和邮箱账户数据。请先确认 SQL 成功执行。
2. 将本目录内 **全部 8 个文件**上传到网站的同一目录（例如 `steins707/`），覆盖旧版。保留 `config.js` 中当前填写的 Project URL 和 publishable key；它是可公开的前端密钥，不能替换为 secret/service_role key。
3. 强制刷新网页。若还是旧界面，在浏览器开发者工具 Application → Service Workers 注销旧 Worker 并清除该站点缓存后刷新。
4. 第一台设备点击“创建新空间”，记下生成的 **6 位数字同步码**（可能以 0 开头）。第二台设备打开同一网页，输入同步码并点击“连接”。旧版 64 位同步码也仍可输入。之后每次操作都会写入云端，其他设备重新打开或返回页面会刷新；网页持续打开时约每分钟刷新一次。

## 安全与数据

同步码等同于该空间的钥匙：任何持有码的人都能读取、编辑和删除记录。**6 位数字容易被猜中，且此版本没有尝试次数限制。**仅适用于你接受这一风险的小范围非敏感使用场景；请勿存储患者信息或其他敏感数据。丢失同步码且所有设备都已断开时，无法从网页找回空间。断开此设备只清除本机保存的同步码，不删除云端记录。药品数据需要联网访问，网页关闭后没有推送通知。

“导出备份”保存 JSON 文件；“导入备份”会替换此空间的全部记录，操作前请先导出备份。旧版邮箱账户中的云端数据不会自动出现；如果你仍能打开旧版，可从旧版手动整理记录或按需另行迁移。旧版纯本机模式的数据也不会自动迁入。

此版本不要求 Supabase Email 登录，也无需启用注册。数据库仅保存同步码的 SHA-256 摘要，不保存明文；网页的浏览器本机仍会保存同步码以便再次连接。升级已有同步码版本时，需要**重新执行更新后的 `schema-sync-code.sql`**，才能启用 6 位码。
